# Chrono — Phase 0

A daily timing-accuracy game. Five rounds, one shot each, same five for everyone,
resets at midnight UTC. No running clock is ever shown — you're scored on how many
seconds you were off in total, and you share that number.

This is **Phase 0**: the complete single-player daily loop with local persistence
and a share card. No accounts, no server, no leaderboard.

## Run it

The game itself has no build step — serve the folder over HTTP (ES modules don't
load from `file://`):

```bash
python3 serve.py
# → http://localhost:8777
```

That covers everything except the share link, which is generated by a Worker. To
run the whole thing, including `/s/` and `/og/`:

```bash
npm install && npm run dev
```

> `npm run dev` passes `--persist-to` a path outside the repo on purpose. The
> assets directory is the repo ROOT, so wrangler's default `.wrangler/` state
> lands inside what it is watching and the dev server reloads forever. The real
> fix is to move the site into its own `public/` directory; the flag is the
> stopgap. Deploys are unaffected — `.assetsignore` keeps `node_modules/`,
> `worker/`, `test/` and the tooling files out of what ships.

### Replay & testing

The once-per-day lock is **live**: one puzzle per real UTC day, keyed to
`todayUTC()`.

- **PLAY AGAIN** on the results screen is replaced by a **NEXT KRONO IN hh:mm:ss**
  countdown once today's puzzle is done. It unlocks on its own at UTC midnight —
  the countdown re-renders the screen in place, no reload needed. SHARE, the
  test-challenge link, and Reset stats all keep working while locked.
- `?dev` / `?date=YYYY-MM-DD` — an isolated test challenge that ignores the lock
  and never writes to stats. **This is the way to replay freely**, and the link to
  share if you want someone to try it more than once a day. The **"Play a test
  challenge →"** link uses it.
- The results screen has **no reset control**. Clearing the lock by hand means
  `localStorage.removeItem('chrono')` in the console — `?dev` / `?date=` is the
  intended way to replay.

### Keyboard

Fully playable without a mouse. The primary control on every screen is focused on
arrival. **Space** starts/stops the hold rounds and Drift; **Enter** submits
guesses; **1–4** pick the brain-game answers (also click / Tab + Enter).

## Rounds

1. **Mark** — hold a clean target (1.00–9.00s, 0.25 steps).
2. **Fraction** — hold an awkward, uncountable target (0.40–9.00s).
3. **Readout** — the machine runs a hidden interval (0.30–9.50s); estimate it
   (scored against actual elapsed, not the intended `setTimeout`).
4. **Drift** — interval production (4.50–8.00s) under a deliberately
   miscalibrated reference. Ticks fire on audio + visual at a mean IOI that is
   **15–25% off a real second**, jittered per tick, and they **stop** at 45–65%
   of the target. You finish in silence. The round tests whether you notice the
   reference is lying and discount it.
5. **Split** — solve one equation, then estimate the whole interval from
   START to your answer. The equation appears immediately (no pre-delay). The
   answer deadline is never shown; leaving the screen ends the round.

## Architecture

Challenge generation, scoring, and rendering are kept in **separate modules with
no shared state**, so Phase 3 can run generation and scoring server-side unchanged.

| File | Role | Pure? |
|---|---|---|
| `js/prng.js` | `cyrb128` + `mulberry32` seeded RNG | ✓ |
| `js/dates.js` | UTC date maths, puzzle number, launch epoch | ✓ |
| `js/daily.js` | **Generation** — date → byte-identical challenge | ✓ |
| `js/scoring.js` | **Scoring** — error, caps, bands, drift, tiers, round 5 outcomes | ✓ |
| `js/storage.js` | Versioned `localStorage`, streak/PB/lifetime/bias | ✓ |
| `js/share.js` | **Share** — the shot group, all variants, and the link codec | ✓ |
| `js/scorecard.js` | **Score card** — one model for the screen and the OG image | ✓ |
| `js/clipboard.js` | Async clipboard + `execCommand` fallback | — |
| `worker/index.js` | The share link: `/s/<code>` and `/og/<code>.png` | — |
| `js/instrumentation.js` | Local event log, `window.__chronoData()` | — |
| `js/app.js` | **Rendering** — DOM, screen state machine, round controllers | — |

### Timing

- Measurement uses `performance.now()` exclusively, captured as the first
  statement in each event handler (never inside `setState`/`useEffect`).
- Round 3 schedules with `setTimeout` but scores against the **actual** elapsed
  time recorded at stop, not the intended duration (`setTimeout` drifts).
- Round 4's tick train is scheduled from a single origin (the start press), so
  `setTimeout` slop can't accumulate across it; measured onsets land within ~6ms
  of the seeded ones. Audio and visual fire from the same callback — the tone
  starts on the audio clock and the flash paints on the next frame, so the skew
  stays inside one frame.
- All durations are stored as **integer milliseconds**; seconds are produced only
  at render time.

### Determinism

Every challenge parameter is drawn from `mulberry32(cyrb128("chrono-" + YYYY-MM-DD))`
in a fixed, documented order (see the header of `js/daily.js`). Two browsers on the
same UTC date get identical targets, durations, equations, drift references, and
deadlines. Round 4's tick train runs on its own derived stream
(`"chrono-drift-" + date`) because it consumes a variable number of draws —
keeping it off the main stream stops the tick count from shifting round 5. `Math.random()` is never used in generation.

> **Puzzle number** counts days since `LAUNCH_EPOCH` in `js/dates.js` — currently
> `2026-09-01` (= #1), the friends-testing deploy date. Moving the epoch shifts every
> puzzle number and nothing else, so set it to the real public launch date when there
> is one. Dates before the epoch are zero/negative; that's expected.

### The hard constraint

**Nothing in this product animates on a repeating cycle.** No pulses, spinners, or
looping keyframes anywhere — a period is a metronome, and it compromises gameplay
integrity. This is a correctness requirement, not a style preference; there is no
`infinite` in `css/styles.css`, by rule.

Round 4 is the one place something fires repeatedly, and it is built to *not* be
periodic: per-tick jitter at 10–14% of the mean IOI, and the train stops partway
through. Its visual tick is the ellipsis of "Running…" — three dots held dim, one
lighting per tick, as a single-frame class swap with no transition (a fade would
smear the onset). Dots never accumulate, so once the ticks stop the screen reads
the same as before the first one and is not a record of how far they got. Visual
energy otherwise lives on the results screen, where timing no longer matters.

### Visual language

Bold, colourful, minimal: each screen is a full-bleed colour field (electric blue,
pink, purple, orange, ink) with huge condensed numerals (Anton), clean labels
(Archivo), and white pill buttons. Times are shown big as `SS:CC`.

### Round 5 anti-cheat

The answer deadline is never rendered and never enters the DOM. Backgrounding the
tab, blurring the window, or refreshing between START and answer scores a flat
2.00s and skips the guess phase.

## Debugging

`window.__chronoData()` returns the full local state and per-round event log
(`roundIndex`, `target`, `actual`, `signedError`, `relativeError`, `band`; round 3
adds `intendedDuration` vs `actualDuration`, round 4 adds `biasDir`/`biasPct`/
`meanIoi`/`jitterSd`/`blackout`/`tickCount`/`followedBias`, round 5 adds
`mathCorrect`).

The band thresholds and both caps are calibrated guesses to be retuned once there
is real data — and only those, so scores stay comparable across the change.

### Round 4 scoring

Drift is scored like any other production round — `|marked − target|`, same bands
— with **one** difference: a looser per-round cap.

| | Cap |
|---|---|
| Rounds 1–3, 5 (`CAP_MS`) | 1.50s |
| Round 4 / Drift (`DRIFT_CAP_MS`) | 3.00s |

The looser cap is the point, not an oversight. The day's false reference drags
the whole player base the same way, so **correlated error is the expected outcome
here**. At the blind rounds' 1.50s cap a large share of players would pile up on
the ceiling on a strong-bias day and the round would stop discriminating. Both
values live in `js/scoring.js`; tune `DRIFT_CAP_MS` once there is real data.

Drift is also flagged `biasEligible: false`, so it stays out of the lifetime
early/late readout: its signed error is deliberately pushed by the reference, so
folding it in would measure the day's bias rather than the player's own clock.

### Round 4 parameters

All seeded from the UTC date, identical for every player. The ranges are
load-bearing — the reasoning is in the header comment of `generateDrift` in
`js/daily.js`, and **narrowing any of them quietly breaks the round**.

| Parameter | Range | Why |
|---|---|---|
| Target `T` | 4.50–8.00s | long enough that the blind stretch bites |
| Bias magnitude | 15–25% | Weber fraction near 1s is ~8–12%: under ~12% the bias is undetectable and the round is just a constant offset; over ~30% the ticks read as obviously wrong and are dismissed for free |
| Mean IOI | 0.75–0.85s (fast) / 1.15–1.25s (slow) | the bias, applied to a nominal 1s |
| Jitter SD | 10–14% **of the mean IOI** | the entrainment kill switch — under ~5% players synchronise and it becomes a metronome, which trivialises this round *and* corrupts later ones. Proportional, never absolute: a fixed SD would make fast days look tighter and leak the direction |
| Jitter clamp | ±2.5 SD | no single gap is absurd |
| Blackout | 0.45–0.65 of `T` | ticks can't be counted to the finish; the error lands in the unsupported stretch |

Ticks fire on **both** audio and visual. Muted players get a materially harder
round — that is intended, and sound-off is treated as a legitimate harder mode.
Nothing compensates for it.

After the mark, one line states the day's bias and whether the player went with
it (sign agreement: a fast reference pulls early, a slow one pulls late):

> Reference ran 22% fast. You followed it.

That line is the entire tutorial for the round.

## The score card

The results screen is the shareable artifact, not a diagnostic readout: the day's
total on the left, one axis row per round on the right, dot placed at the round's
signed error. `js/scorecard.js` builds that as **data**, and three renderers read
it — the screen (CSS grid, `js/app.js`), the Open Graph image (flex/absolute
HTML, rasterised in the Worker) and the text shot group. None of them re-derives
placement, so they cannot drift apart.

| Round | Marker |
|---|---|
| perfect | 💎 at centre (a drawn gem in the OG image — see below) |
| error < 20cs | green dot |
| 20–49cs | amber dot |
| 50cs+ | **neutral** dot |

**There is no red.** SHARE sends this card, and a red failure state is exactly
what the share must not carry. It isn't needed either: position already encodes
how far out a round was, so colour only has to mark the good end.

The scale is the same fixed 0.50s half-range the text block uses and is **never
normalised to the day**. A pegged round keeps its dot at the extreme of the axis
and adds a hard stop just past it, so a clipped value can't read as a
merely-large one.

Placement on the card is **continuous**, not snapped to the block's 15 cells: the
text block quantises because monospace forces it to, and snapping here would put
two rounds 0.02s apart on the identical pixel. Same scale, same clamp, same
printed values — only the resolution differs. Each row still carries the cell it
*would* occupy (`row.index`) so the correspondence stays testable.

### What SHARE actually hands over

The card, as an image — not a description of it, and **not through an OS share
sheet**. SHARE copies, which keeps the player on the results screen and lets them
paste wherever they were already going instead of picking a destination out of a
list first.

| | Path | Result |
|---|---|---|
| 1 | `clipboard.write` with **both** `image/png` and `text/plain` | the paste target picks: a message thread takes the image, a text field takes the caption and link |
| 2 | `clipboard.writeText` | caption + link, when the browser has no image clipboard or the card didn't render |

```
Krono #2 — 0.58 seconds off
https://<site>/
```

The link points at `/s/<code>`, the result page. Where the IMAGE flavour wins it
costs nothing — the paste target never sees the text. Where the TEXT flavour wins
(Slack, Discord, Notes, email, any plain text field) the link unfurls into the
card from that page's OG tags, instead of arriving as a bare invite. Either way
the page leads on to today's puzzle.

The card itself carries no tier tag and no URL stamp — just the puzzle number,
the total, and the five rows. **A consequence worth knowing:** X and WhatsApp
take the `image/png` and silently discard the `text/plain`, so an image pasted
there now carries no route back to the site. `text/html` is not a way round it
either — both sanitise pasted HTML to plain text and will not fetch a remote
`<img>` from it. If acquisition through those two matters, the address has to be
in the artwork.

The PNG is fetched from `/og/<code>.png`, and in rung 1 the blob is passed to
`ClipboardItem` as a **promise**, not an awaited value: Safari only keeps the
user gesture alive across the fetch if the item is constructed synchronously
with one.

`/og/` is served by the Worker, so **`python3 serve.py` cannot produce the image**:
SHARE falls to rung 2 and copies text only. Use `npm run dev` when testing
sharing.

> `/s/<code>` still exists, is still tested, and still renders the card with full
> OG tags — but nothing in the app links to it any more. It is the route to reach
> for if a link-preview share ever comes back.

| Route | Response |
|---|---|
| `/s/<code>` | a page whose `og:image` is the card |
| `/og/<code>.png` | that card at 1200×630 |
| anything else | falls through to the static assets |

A whole day packs into the path, so nothing is stored server-side:

```
/s/28.4.0p.6.67.-26.C
     │  │              signed CENTISECONDS per round, `p` = perfect
     │  puzzle number
     └─ tier initial (R | C | M | O) at the end
```

Two decimals is exactly the share's display resolution, so nothing is lost. A
**malformed code is not an error** — it falls through to the static assets, so a
truncated link lands the visitor on the game with the site's generic preview.

**Spoiler safety:** signed error, perfect flag, puzzle number and tier — nothing
else. No target durations, no marked times, and never Round 4's tick bias.

**Unverified by construction:** anyone can hand-write a code claiming a flawless
day. With no backend there is no way around that, and the link is a bragging
artifact rather than a record. Sign it when there are accounts to sign for.

### Why the OG card draws its own glyphs

Satori has only the font buffers the Worker hands it, so `▸` and `💎` in the
markup come out **blank** — and a blank marker on a perfect round would silently
erase the best result in the game. The gem is an inline SVG and the peg is a bar,
neither of which depends on a font or a network fetch at render time. A test
asserts the OG markup contains no glyph it cannot draw. (`workers-og` never
invokes `loadAdditionalAsset`, so the usual Twemoji route isn't available either.)

## The share block — shot group

Replaces the old `🟥🟩🟩🟨🟩` + "0.81s off" block. Squares discard sign and
magnitude, which is all this game actually produces, and a bare seconds figure
means nothing to someone who doesn't play. The shot group plots signed error per
round on a shared axis, so **a tight cluster and a wide scatter are told apart
pre-verbally by a stranger**. That property is the format; every constant in
`js/share.js` exists to protect it.

```
KRONO #2122          0.81 s/day
MARK   ·············●·    +0.42
FRAC   ······●········    −0.04
READ   ··········●····    +0.19
DRFT   ·····●·········    −0.11
SPLT   ········●······    +0.05
early  ───────┴───────     late
PATIENT / DRIFTING · CHRONOMETER
```

`js/share.js` is **pure**: no clock, no locale lookup, no network, no DOM. Same
input, byte-identical output on every platform. Numbers go through `toFixed`,
which is locale-invariant by specification — never `toLocaleString`, which would
render `0,81` in half the world and break the shared artifact.

### The axis

| | |
|---|---|
| `AXIS_WIDTH` | 15 (must stay odd) |
| `AXIS_HALF_RANGE_S` | 0.50 — tune to ~P90 of per-round absolute error, so ~10% of dots peg |
| marker | `●` normal · `◈` perfect, at centre · `◂`/`▸` pegged at an edge |

`cellIndex(e) = 7 + round(clamp(e / 0.50, −1, +1) × 7)`, rounding **half away
from zero** so early and late move the same distance from centre.

**The scale is fixed, never adaptive.** Normalising to the day's own error range
makes an excellent day and a terrible day render identically, which destroys the
only property that makes the format work. A bad day *should* look pegged. That
is information, not a rendering bug. The `◂`/`▸` arrowheads cost one character
and stop a pegged dot reading as a merely-large one.

### Reconciliation

Per-round values are rounded to 2dp **first**; the headline is the sum of their
absolute values; the axis places the rounded value too. People add the column —
if it doesn't reconcile the block looks broken and the format loses credibility.

The displayed total can therefore differ from the internally stored score by up
to ~0.025s. **The stored score stays authoritative** for tiers, streak and
personal best. Don't "fix" the difference by printing the unrounded total. The
results-screen hero shows the *reconciled* headline, because the block sits
inches below it and the two cannot disagree on screen.

Negatives use **U+2212 MINUS SIGN**, not an ASCII hyphen — a hyphen is narrower
than the plus it pairs with and the value column stops lining up.

### Signature and escalation

`{BIAS} / {CONSISTENCY} · {TIER}`, from the same rounded figures:
`|mean| <= BIAS_T` → `TRUE` (the reward state, and the horological term for a
movement on rate), else `EAGER`/`PATIENT`; population SD against `CONSIST_T` →
`STEADY`/`DRIFTING`. Ship values `BIAS_T = 0.08`, `CONSIST_T = 0.15`.

Structure changes with rarity, not just content:

| | when | what changes |
|---|---|---|
| **A Standard** | no perfect rounds | the block above |
| **B Marked** | some perfect | `◈` at centre on those rows — no extra lines, the scarcity does the talking |
| **C Flawless** | all perfect | numerals disappear entirely; ~one per year globally |
| **D Streak** | streak >= 5 | one trailing line, appended. Below 5, nothing — `🔥 1` is worse than silence |

### Variants

- **compact** — seven graded characters `⇜ ← ‹ · › → ⇝`, same `cellIndex` maths
  bucketed into 7 symmetric bins. A flawless day renders `· · · · ·`: the
  quietest glyph for the rarest outcome.
- **monthly** — one rarity-graded character per day, `▫ ▪ ◆ ◈ ✦`, graded from the
  day's tier with `✦` reserved for a flawless day. **Unplayed days render as a
  space, never a "worst" glyph** — a gap is neutral; a black mark for not playing
  is punitive and suppresses re-entry. `renderMonthly()` and its tests are live,
  but the card redesign took its entry point off the results screen; it needs
  re-siting.

### Platform routing

The block only reads correctly in monospace: in a proportional font the
four-character labels have unequal widths, the left edge of the axis skews, and
the cluster read is destroyed. `shareForPlatform()` routes it.

| Platform | Path |
|---|---|
| Slack, Discord, Telegram, WhatsApp | triple-backtick fence |
| iMessage, Instagram, stories | **image** (`js/share-image.js`) |
| X | compact variant, or image |
| Clipboard | raw text |

The image path rasterises the *same string* as the text path, so the two can
never drift. Never ship a proportional-font text path and hope.

### Spoiler safety

Signed error is independent of target duration, so the block leaks nothing by
construction. Never add target durations, marked times, or Round 4's tick bias —
the in-app `Reference ran 22% fast` line is the one genuine spoiler in the game
and must not reach the share.

### Accessibility

The ASCII block is noise to a screen reader, so it is `aria-hidden` on the
results screen with `shareSummary()` beside it as prose, which doubles as the
image's alt text:

> Krono 2122. Rate 0.81 seconds per day. Mark 0.42 late, Fraction 0.04 early,
> Readout 0.19 late, Drift 0.11 early, Split 0.05 late. Patient, drifting.
> Chronometer.

### Tests

```bash
npm test
```

Golden strings for the standard, all-pegged and two-perfect days, plus the
flawless, compact and monthly variants, the card model, and the link codec. They lock the **format**, not just the
code: if one moves by accident the block has stopped being byte-identical across
players, which is the property everything else rests on.

### Do not

- Reintroduce `🟥` or any red failure state anywhere in the share, the card
  included.
- Normalise the axis per-day.
- Add a second number to the headline — every extra figure halves the odds any
  of them are read.
- Widen the axis beyond 15 to gain resolution.
- Render a "worst" glyph for unplayed days.
- Emit a glyph in the OG card that the Worker's fonts don't carry.
